## 1. 本轮目标与边界

解决三个问题：失效模型仍可选择、做题等待过长、手机界面操作与阅读效率不足。Android 真机优先；网页版同步模型迁移、请求策略与必要的流式链路，避免两端行为分裂。

保留 Kotlin / Compose / CameraX / Room 和现有网页技术栈。保留相机、相册、最多 9 图、EXIF 校正、完整图加裁剪图、题型选择、追问、历史、收藏、隐私确认及密钥保护。禁止为换 UI 重写整个项目，禁止以清库或删除历史规避兼容。

本轮不引入独立 OCR 服务、账号、云同步、搜索服务或并发调用多个模型。Pro 只作为高级纯文字选项；图片题优先使用具备图片能力的 Flash。同一道题默认只发一次解题请求，点击展开已有解析不能再次收费调用。

## 5. M：模型配置与兼容升级

### M1. 将“选模型”和“选思考强度”解耦

建立单一模型目录/能力描述，两端保持同一规则：模型 ID、显示名、输入能力、可用强度、是否官方预设。Android 可新增 `ModelCatalog.kt`、`AnswerMode.kt`；网页新增相应小模块即可，不需要引入框架。

- 普通用户看到：Flash（支持拍题）；高级设置可选 Pro（仅文字）。主界面以做题模式表达速度和深度。
- 图片存在且选中 Pro：在发送前提示“当前模型不支持图片，切换到 Flash 后解析”，提供明确切换操作；不得悄悄丢弃图片继续答题。
- 自定义模型保留在高级设置。能力未知时说明未验证，不能假设所有兼容接口都支持图片、思考参数、JSON 或 SSE。
- 兼容服务可以保存明确的能力配置；参数不支持时给出可操作错误，不做无声降级或连环重发。
- 请求开始时固定 `baseUrl/model/mode/promptVersion` 快照；中途修改设置不能改变正在执行的请求和记录标签。

### M2. 迁移现有设置，保证幂等

仅当 URL 规范化后属于 DeepSeek 官方主机且为受支持的 OpenAI 接口路径（根路径或 `/v1`）时自动迁移。不得通过字符串 contains 判断官方主机，不得误改自定义代理。

| 旧官方设置 | 新设置 | 升级提示 |
| --- | --- | --- |
| `deepseek-chat` | `deepseek-flash` + 快速 | 已迁移旧模型，可切换思考模式 |
| `deepseek-reasoner` | `deepseek-flash` + 详细 | 保留原有偏重推理的使用意图 |
| `deepseek-v4-flash` / `deepseek-v4-flash-vision-exp` | 规范为 `deepseek-flash` | 保留有效模式；不显示为失效错误 |
| 当前 Flash/Pro | 保留模型；无模式时采用经效果验收的默认模式 | 展示一次新模式说明 |
| 自定义地址或未知名称 | 保留原值 | 显示可用性验证入口 |

记录迁移版本，单次完成原子写入；第二次启动不得重复覆盖用户新选择。保留 Key、Base URL、历史、收藏、原始历史中的模型名称。网页处理 localStorage 旧值，不能只改 DEFAULT_SETTINGS。

### M3. 将连接检测拆为明确的两种证据

1. “检查连接”：拉取 `/models`，解析模型 ID 与能力；显示接口可达、选中模型是否存在。网络失败不删除本地预设或已保存设置。
2. “验证模型”：用户主动触发一次极短文字请求，显式关闭思考，输出预算约 32–64 token，确认有可读回答。显示此次测试会调用接口。
3. 图片能力以元数据和官方能力表共同校验；真正图片链路由验收样例验证。不能把一次文字验证称为图片解析已验证。
4. 保存密钥不强制依赖联网验证，保留现有离线保存能力。分别记录“已保存 / 连接已检查 / 模型已验证”，避免一个绿色成功状态掩盖不同含义。
5. 模型列表刷新可手动进行，缓存可离线使用，不在每次做题前多发 `/models`。

## 6. S：真实速度与等待体验

### S1. 三档模式与输出预算

下列预算是实施起点，不是官方推荐值或已经验证的最佳值。经过样本对照后可调整，但需报告理由。

| 模式 | 默认模型 | 显式参数 | 内容与初始预算 |
| --- | --- | --- | --- |
| 快速 | Flash | `thinking: {type:"disabled"}`；不再发送启用思考的 effort | 答案、核心依据、题干和必要风险；选择题每项一句；最多约 2–3 条知识点/思路，`max_tokens` 3072 起 |
| 标准 | Flash | `thinking: {type:"enabled"}`, `reasoning_effort:"low"` | 完整选项判断与简明讲解，`max_tokens` 8192 起 |
| 详细 | Flash | `thinking: {type:"enabled"}`, `reasoning_effort:"high"` | 更完整的讲解和鉴别，`max_tokens` 16384 起 |

新用户拟默认快速；**只有第 9 节质量门槛达标才采用这个默认值**，未达标则默认标准，并保留用户可选快速。旧 reasoner 用户按迁移表保留详细意图。不要因为快速有错误就自动多请求一次模型；应呈现信息不足或让用户主动切换模式重答。

实现要求：

- 非思考与思考参数由统一请求构造器生成，不能出现 disabled 与启用思考的 effort 相互矛盾。
- 思考请求不发送无效的 temperature 来制造“更确定”的假象。非思考可保留适当温度；不要声称降低 temperature 必然提速或保证正确。
- 分开“做题模式”和“结果折叠”。折叠已生成内容只改善阅读；真正减少耗时需要减少生成文本和思考量。
- 优化提示词中的重复叙述，保留医学题意、否定词、单位、逐项核对、看不清明确告知等要求。要求输出简洁的解题依据，不要求展示模型内部思考全文。
- 保持现有 `AnalysisResult` 可读；快速模式允许部分拓展数组为空，UI 正确隐藏空区块。不要丢掉信息不足、图文冲突或关键风险。
- 两端都启用 JSON Output，并继续做必需字段、题型、选项数量/答案匹配、状态校验。prompt 给出合法 JSON 示例，不能把枚举表达式当 JSON 示例。
- 检查 finish_reason；length、空内容、格式异常都不能写为 completed。预算不足应显示“输出未完成，可用更高预算重试”，不盲目自动重复消费。
- Android 现有 confidence 为字符串、网页主要按数值处理，保持兼容规范化；不借本轮迁移让旧记录变成错误。模型自报把握不能用作唯一质量判定，也不能展示成真实正确率。

### S2. 接通完整 SSE 链路

推荐流程：

`点击解析 → 本地建任务并进入结果页 → 准备图片 → 上传 → 等待模型 → 接收内容 → 校验 → 保存完成`

Android：新增可测试的流式读取层，按 Flow/事件输出进度。底层 Call 应与协程取消绑定，读完关闭 body。禁止继续调用 `body.string()` 把整个 SSE 当 JSON。

网页：前端改用 ReadableStream + 持续 TextDecoder；Node 代理收到上游头后即转发，逐块写回，支持背压，不能先 `response.text()`。客户端断开时取消上游，避免服务器仍继续收费生成。已有非流式响应和错误体仍须可处理。

解析器至少正确处理：

- 单个事件跨多个网络块、一个网络块含多个事件、UTF-8 中文跨块、LF/CRLF、空行和 `: keep-alive`。
- `delta.content`、只有角色无内容的块、只有思考而无最终内容的块、缺失 choices 的兼容块、最终 usage、finish_reason、`[DONE]`、中途错误和意外 EOF。
- reasoning_content 只驱动“正在思考”等状态，不能作为正式答案渲染或混入 JSON；本产品无工具调用，不把历史内部思考加入追问。
- 根据当前官方格式读取结束块的 usage，同时容忍兼容服务将 usage 放在独立末尾块；缺失/中断则标未知，不能伪造 0 或复用上一题用量。
- 开始 streaming 后已发响应头的代理错误应作为流中错误/明确断流处理，禁止再写一次 JSON HTTP 响应头。
- UI 更新合并到约 50–100ms 一次，避免每个 token 都触发整个页面重组；数据库只在阶段变化或最终结果时必要写入。

**提前展示答案的约束：**

同一次请求中优先输出 `status`、`question_type`、`answer`、`answer_text`、`warnings`，其后输出题干与其他讲解。使用经过测试的增量 JSON 字段读取器，只有完整字段值均已读完并校验后，才显示“答案预览 · 解析尚未完成”。不能用正则抓取第一个 A/B/C，不能对半截 JSON 补括号后当成最终结果。

预览需要状态、答案及风险字段齐全；字段未到齐就继续显示接收中。模型未按建议顺序输出时允许晚展示，不得猜。最终严格解析通过后替换为正式答案；断流、取消、截断时保留“未完成”标签并停用分享正式结果等动作。needs_confirmation 优先显示缺失信息；最终与预览变化时清楚刷新，禁止把预览独立保存为成功答案。

若实施模型选择暂缓增量字段读取，必须将“提前看到答案”列为未完成，本轮 S2 不可整项报通过。不得用第二次后台生成详解代替同请求流式方案。

### S3. 可取消、可恢复且记录正确

- 增加任务状态与 requestId，例如 preparing/uploading/waiting/receiving/validating/completed/failed/cancelled/interrupted。业务结果 status 与网络任务状态分别建模。
- 取消需真的中止 HTTP：协程取消重新抛出 CancellationException，不能被现有通用 catch 包装成网络失败。取消后旧请求迟到的块不得覆盖新请求。
- 同一题同时只允许一个解析任务；重答和追问互斥到不会交叉覆盖上下文。按钮双击、快速切换模式均不能发重复请求。
- 请求使用题目/配置/图片的稳定快照；在任务执行时禁止修改或删除被引用的图片。图片文件所有权在草稿和题目之间明确转交，不能清草稿时误删题目图片。
- 配置、模型、模式、prompt 版本和测量数据与实际请求对应。重答成功后更新实际使用的模型，失败保留旧答案及上下文；旧追问可在新版本成功提交后清除或归档，不能在网络调用前销毁。
- 普通页面返回与旋转不取消任务，返回后能继续看到当前状态。应用进程被杀后不假装后台任务还在运行：下次启动把未完任务标为 interrupted，并给“重试”。本轮无需新增长时间后台服务。
- 点击解析后立即进入对应结果页；如果建任务失败，停留原页并保留草稿。任务失败/取消后支持带回原题重试，不丢图片和文字。
- 限定连接、首个有效事件等待、内容停滞、整体请求的超时；推荐起点连接 15s、首个非保活事件 45s、无有效内容进展 45s，整体按快速/标准/详细 120/180/240s。实验后调整并报告。保活不重置“无有效进展”计时，详细模式的有效思考事件可算进展。
- 计时覆盖请求与响应体，finally 清理资源。先提供手动重试；本轮不要求自动重试，以免重复计费和尾延迟扩大。401/402/格式/不支持能力必须给明确原因。

### S4. 图片与上下文的轻量优化

先测量再决定是否进一步优化，不把“图片数量多”直接等同于 CPU 解码瓶颈。

- 保留当前 1800px / JPEG 86 作为默认，网络请求前避免重复解码/编码。默认不使用 detail=low，不为压缩而损害否定词、数值、单位或波形。
- 同一图片不重复加入请求；保留完整图与人工裁剪图的不同用途，不能按相似度误删有效局部图。提交前可展示图片数和预计上传体积。
- 仍保持 9 图和现有应用体积限制。对序列化后的请求体做边界检查，考虑 Base64 约 4/3 膨胀与网页代理现有 30MiB 上限；官方上限更高也不代表应用需要放开。
- 多图导入只有证据表明明显耗时时，才做有界并发（建议最多 2 张）与按原顺序汇总；不能同时解码 9 张导致内存峰值暴涨。
- 原图追问默认不附带，保留已有行为；需要看细节时由用户打开。追问使用原题摘要与最近完整对话，按预算裁剪，不能只按条数无限增长，也不能截断半轮造成上下文误解。
- 本轮不默认开启解题结果缓存。已有历史重开直接读取本地结果；“重新解析”明确会重新调用。避免缓存错误答案影响性能统计。

## 7. U：手机 UI 与交互规格

### U1. 首页：先拍题，再补充

首屏优先级：标题和简短说明 → 拍照/相册 → 图片预览 → 可选文字补充 → 题型/做题模式 → 隐私确认 → 固定底部解析按钮。长帮助文字折叠，不抢占首屏。

- “拍照”是主要入口，“相册”是并列次要入口；未配置 Key 时用紧凑横幅提供“去设置”。
- 无图状态给短提示；选图后显示编号、图数与体积。点击缩略图打开编辑面板，集中提供旋转、裁剪、排序、删除，替代每张图下密集小图标。
- 保留“保留原图并添加”“替换当前图”两种明确裁剪操作和 9 张上限，不因 UI 简化破坏上一轮修复。
- 题型默认自动判断，常用选项紧凑展示；文字输入可折叠但用户一键可达。
- 模式选择显示“快速 / 标准 / 详细”及一行差异说明；高级型号放设置。
- 解析按钮固定在内容区底部、底部导航上方，适配 IME、手势栏和系统安全边距。不能以绝对叠层遮住隐私确认或输入框。
- 有图片时仍要求用户确认无身份信息；隐私说明用短文加展开详情，不移除确认。纯文字提交也保留现有必要确认，除非产品另行明确调整。
- 按钮不可用时可见原因，如“先添加题目”“正在导入图片”“请先确认图片隐私”，避免只变灰。

### U2. 解析中：呈现真实进度

显示当前阶段、已耗时、图片数和“取消”。上传进度只有在实际可计量时显示百分比；等待模型用不定进度。一次多模态请求内部的识别/推理不可精确区分，不能按计时器轮播“识别完成/校验完成”。

首个思考事件、首个正式内容、预览字段完整、最终校验等实际事件驱动状态。超过约 20s 展示“仍在等待模型响应”及耗时，不写虚假剩余秒数。预览出现后保留“生成中”，不提前变成功。删除现有“不要离开当前页面”的笼统要求，改成与 S3 生命周期一致的说明。

### U3. 结果页：答案置顶，细节按需展开

建议布局：

```text
题目解析                         收藏  更多
模式 · 本次耗时                       原题
┌ 参考答案 / 信息不足 ─────────────────┐
│ B / 多选 A、C / 简答正文             │
│ 核心依据或必须补充的信息              │
│ [复制答案] [查看解题依据]             │
└────────────────────────────────────┘
关键警示（存在时直接可见）
选项分析（选择题默认展开简短列表）
解题依据（简明）
知识点 / 易错点（可折叠）
原题与图片观察（可折叠，点图放大）
─────────────────────────────────────
追问这道题…                [发送]
```

- AnswerCard 放在题目图片和大块元信息之前。状态栏可保留小缩略图/原题入口。
- 单选/多选答案字母可放大；填空与简答用正常正文层级并可选中，不把整段简答渲染成 displaySmall。
- 识别到的题干要保留“一键核对/修改”，折叠只减少占屏，不隐藏校对能力。
- needs_confirmation / out_of_scope 必须用相应状态表达，不显示绿色成功图标或确定答案；关键警示不能折叠进深处。
- 复制、收藏就近；分享、补图、修改题干、重新解析集中“更多”或明确次级入口。重答会调用接口，保持可见说明。
- 耗时可见；模型 ID 和 token 用量放可展开的“调用信息”，缺少数据时显示未知/不显示，不能用模型输出伪造用量。

### U4. 追问、历史与设置

- 结果页底部放可用的追问输入；键盘打开后输入与发送按钮仍可见。不要让用户必须滚过所有解析才能提问。
- 提供“为什么不是 A”“解释关键概念”等快捷问题；点击明确发送或填入待发送输入框，行为保持一致。
- 追问流式显示正文，支持停止，失败保留问题和输入。附带原图是显式开关，默认关闭。
- 历史按日期分组，展示题目摘要、题型、答案/状态、收藏；搜索框和“仅收藏”易达。失败/取消/中断不能都变成空白历史项。
- 设置分为“密钥与连接”“做题模式”“数据与隐私”“高级接口”。正式预设没有 chat/reasoner；保存、检查连接、验证模型分别标明状态。
- 显示应用版本/build 标识，便于确认手机装的就是待验收 APK。

### U5. 视觉与可用性

沿用现有青绿色基调和 Material 3，重点优化层级、留白、密度，无需更换品牌。

| 项目 | 建议规范及验收点 |
| --- | --- |
| 间距 | 页面左右 16dp；模块间 12–16dp；主要卡片内边距 16dp；圆角 12–16dp |
| 字体 | 正文约 16sp，辅助 12–14sp；优先保证题目/解析可读，避免大量小字 |
| 点击 | 主要点击目标至少 48×48dp；可见图标可较小，但布局与语义触控区域必须足够 |
| 状态 | 正确/不确定/失败配合图标和文字，不能只用颜色区分 |
| 适配 | 360dp/412dp 宽、浅深主题、字体 1.0×/1.3×；长题干、多选、长简答不溢出 |
| 滚动 | 长结果采用 LazyColumn 或等价惰性列表；流式输出时用户上滑后不强制拉回底部，提供回到底部按钮 |
| 动画 | 少量状态过渡，避免流式期间持续大面积动画；TalkBack 能读出按钮与状态 |

视觉验收以实际 Android 渲染截图和操作为准，Compose Preview、网页截图均不能代替真机。

## 8. B0：埋点与对照方法

用单调时钟记录相对时长，requestId 串联：点击、图片准备结束、上传结束、响应头、首个非保活事件、首个 content、首次可用答案预览、最终内容结束、校验/落库结束。Android 可借 OkHttp 事件记录上传；网页无法精确获取上传完成时就记未知，不虚构阶段。

建议输出测试 CSV 字段：

`run_id,sample_id,build,model,mode,prompt_version,kind,image_count,request_bytes,prepare_ms,upload_ms,first_event_ms,first_content_ms,answer_preview_ms,total_ms,finish_reason,prompt_tokens,completion_tokens,reasoning_tokens,result_status,answer_match,error_category`

时长均说明起点；默认相对“点击解析”。拿不到 reasoning_tokens 就留空。只有模型输出文本/答案、Key、图片内容等敏感数据都不进入普通诊断日志；题目对照使用虚构或已脱敏固定样例和 sample_id。

先测旧构建可用的 Flash 完整链路，不能把已失效模型的等待失败当正常解题性能基线。若旧版本不可正常完成，保留失败证据，另做相同新客户端 high/low/disabled 参数对照，并说明它不能完整替代旧版实测。

## 9. A：验收数据集与通过标准

### A1. 固定质量集

先准备 40 道经人工核对标准答案的学习题，题目和标准答案在实施调参前固定。其中至少：

- 10 道纯文字题、10 道清晰拍照/截图题、10 道多图或表格/心电图等图题、10 道低清/缺项/图文冲突等应提示不确定的题。
- 跨组覆盖单选、多选、填空、简答、否定问法、数值与单位、相似选项。构成与样例 ID 一起交付。
- 选择题按答案集合严格比对，多选少选/多选均错；填空和简答事先写明评分点。图题同时检查题干关键数字/单位/否定词识别。
- 不能让实施模型自己出答案、自己评分后宣布通过；参考教材/课程答案由人工确认，自动比对只是辅助。

每题分别运行旧版可用基线与拟发布默认模式；另跑标准/详细以检查模式行为。故意信息不足的题单独评估，不混入可回答题正确率分母。

质量门槛：

| 指标 | 门槛 |
| --- | --- |
| 可回答题默认模式 | 总分正确率至少 90%，且相对基线下降不超过 5 个百分点；基线更高时两条件同时满足 |
| 图片/多图子集 | 相对基线新增错误不超过 1 题；关键数字、否定词与单位误读逐例披露并人工复核 |
| 信息不足集 | 至少 9/10 明确提示需补充/核对；不能编造看不清的信息后给确定答案 |
| 新增严重错误 | 如把缺失关键信息当确定事实、丢图仍称已读图，任何 1 例均需修复或调整默认策略后重测 |
| 样本解释 | 40 题是本轮回归门槛，不代表普遍准确率保证；发布说明不得将其包装成医学能力保证 |

若快速未达标，不通过“默认快速”；切回标准，并重新测量其速度。不得删除难题、改答案或只报告成功样本。

### A2. 固定速度集

从质量集中固定 15 道：文字 5、单图 5、多图 5。每道每个对照版本运行 3 次，交错顺序，保存全部结果。至少 45 次/版本，按类型报告 P50/P95、成功率与失败原因。不同模式单独统计；未完成请求单列并按超时边界纳入等待分析，不能通过丢弃失败请求让 P95 变好。

固定同一手机、网络、图片、模型服务时段范围与构建类型；冷启动/首次图片准备与热态分开标记。不用流式动画或首个无意义 token 代替“答案出现”。

| 指标 | 通过标准/优化目标 |
| --- | --- |
| 点击反馈 | 本地可观测反馈 ≤200ms，不能连续点出多请求 |
| 流式显示延迟 | 收到可用事件到界面更新 ≤300ms；按已完整校验的字段显示答案预览 |
| 端到端完整结果 | 拟发布默认相对有效基线总体 P50 至少降低 30%；各题型 P95 不得恶化超过 10%；同时质量门槛达标 |
| 取消 | 点击后界面 ≤1s 退出生成态；正常测试网络下客户端主动取消上游读写 ≤2s，服务端计费停止时间不由客户端承诺 |
| 绝对体验目标 | 正常网络下快速单图 P50 首次可用答案 ≤12s、完整结果 ≤25s；多图完整结果 ≤40s。属于项目目标，受服务波动影响，未达到需据实解释 |

30% 改善及质量门槛是本轮优化验收条件，尚无测量证明能够达到。若达不到，提交真实瓶颈与数据，不能写“提速完成”。不为凑指标默认降为低清图、不输出风险、不做必要解析。
