### R1：Android 图片导入

入口：`app/src/main/java/com/xjb/medicalquestionai/data/ImageStore.kt`，`importImage()`。

原因：先设置 `inJustDecodeBounds = true`，再对 `openInputStream(...).use { decodeStream(...) }` 的返回值使用 `?: error(...)`。尺寸探测正常也返回空 Bitmap，因此合法图片会被当作读取失败。

修复要求：

- 分开判断输入流能否打开、尺寸是否有效和第二次像素解码是否成功，不以尺寸探测返回 Bitmap 与否判断成功。
- 输入流可靠关闭；失败时不遗留不完整图片文件。
- 保持 EXIF 显示方向校正、等比缩放、最长边 1800 px、JPEG 质量 86，以及元数据不随重新编码的图片传播的现有设计。
- 不要把按 EXIF 纠正镜像方向误当作禁止任意镜像而移除。
- 保持最多 9 张的规则和可读的导入失败提示。

验收：

- 使用 Android 运行环境的回归测试，覆盖合法 PNG/JPEG 导入、读取尺寸、生成文件、损坏数据和无法打开的 URI。测试不能把 `BitmapFactory` 全部模拟成成功来绕过此缺陷。
- 检查带 EXIF 方向的图片导入后方向正确；大图等比缩放，重编码结果不保留测试用的敏感 EXIF 字段。
- 在模拟器或真机验证相册导入；CameraX 拍照回传流程需有设备验证证据。模拟器未覆盖的真机相机部分单独标记。
- 若环境无法运行 Android 测试，仍提交回归测试与运行命令，报告“未运行”，不能标记该项验收通过。

### R2：裁剪保留完整图

入口：

- Android：`ImageStore.crop()`、`MainViewModel.cropImage()`、`ui/screens/NewQuestionScreen.kt`。
- 网页：`web/assets/app.js` 的裁剪交互、`web/assets/images.js`。

当前裁剪覆盖选中图片，缺少直接保留完整画面并增加局部图的操作。修复采用以下默认行为，减少实现歧义：

- 提供清楚的“保留原图并添加裁剪图”操作，默认使用该行为。
- 新裁剪图拥有独立 ID、文件路径或独立图片数据，插入原图之后；原图保持不变。这里的原图是应用当前保留的完整画面，不承诺保存未经压缩的原始文件。
- 如保留“替换当前图”，将其作为明确的次级操作，不能与保留原图混淆。
- 已有 9 张时阻止新增并给出提示，不得静默覆盖原图、删除其他图或突破限制。取消或失败不改变原列表。
- 正确更新尺寸、大小、预览及提交顺序；删除其中一张不影响另一张。题目删除、清空历史后清理对应 Android 文件。

验收：合成一张带边框、四角标记和局部文字的图片，检查裁剪范围、原图内容不变、新图独立性、取消、失败、9 张上限，以及保存后重新打开与提交时的顺序。针对原图不变和文件独立性补充回归测试。

### R3：密钥与网络说明

入口：根 `README.md`、`docs/PRIVACY.md`、`docs/ARCHITECTURE.md`、`web/README.md`，以及网页版设置页说明。

修复要求：

- Android：说明密钥由 Android Keystore 支持的 `EncryptedSharedPreferences` 保护。
- 网页版：明确默认记忆密钥开启，密钥以明文写入 `localStorage`；关闭记忆后使用 `sessionStorage`。不要将输入框掩码、存储位置在本机或 sessionStorage 描述为加密。
- 校准刷新与关闭标签页的说明：sessionStorage 通常在同一标签页刷新后仍在，不应写成“关闭记忆后刷新就必须重新输入”。
- 说明网页请求经 Node 代理转发，代理进程能够接触密钥和请求内容；默认监听 `127.0.0.1`。不要写成浏览器仅与 DeepSeek 直接通信。
- 删除“所有版本的 Key 都加密”等概括性错误表述。
- 核对自定义 Base URL 的真实行为。Android Manifest 禁止明文流量，设置界面却接受 HTTP：应统一为 Android 只接受 HTTPS，并提供明确校验提示。网页版如保留 HTTP 以支持本地测试，说明默认 DeepSeek 使用 HTTPS，自定义 HTTP 不具备传输加密。
- 不要求把网页版改造成账号系统，也不需要引入浏览器自制加密方案。

验收：检查 Android、浏览器持久/会话存储、清除密钥操作与文案一致；检查设置和文档不再做错误加密承诺。提交验证截图或文字记录时遮挡密钥。

### R4：网页版追问 token 用量

入口：`web/assets/api.js` 的 `askFollowUp()`、`web/assets/app.js` 的 `sendFollowUp()` 与追问消息渲染。

修复要求：

- 将追问返回值由纯文本改为携带回答和用量的对象，并同步所有调用方。
- 从响应顶层 `usage` 读取 `prompt_tokens`、`completion_tokens`、`total_tokens`，保存到对应助手消息；在该条追问回答旁显示用量。
- 刷新或重新打开历史后仍可查看该次用量；旧历史没有 `usage` 时能正常显示。
- 接口未返回用量时，显示“未提供用量”或隐藏用量，不用 0 表示确定没有消耗，不估算费用。
- 演示模式如提供模拟用量，显式标注为模拟值；不得与真实接口统计混淆。
- 本项不要求跨题目费用汇总，不能顺便删改现有多轮上下文和附图能力。

验收：使用本地模拟接口验证有用量、无用量、旧记录、接口失败四类场景；核对网络响应、持久化消息、页面展示三者一致。至少为真实响应解析与旧数据兼容添加可重复的测试。

## 3. 验证分层与执行顺序

1. 修复与回归：完成 R1，并运行针对该缺陷的 Android 测试。
2. 功能修复：完成 R2、R3、R4，运行相应回归。
3. Android 基础检查：运行 `testDebugUnitTest`、`lintDebug`、`assembleDebug`；设备连接后运行 `connectedDebugAndroidTest`。记录工作目录、命令、环境、退出状态、报告位置及未解决的警告。
4. 网页验证：先检查相关 JavaScript 语法，再通过本地服务验证图片导入/裁剪/历史和追问用量。API 协议与异常场景可使用本地模拟服务，但必须标注模拟。
5. 设备端到端：验证拍照/选图 → 完整图+局部图 → 解析 → 修改题干重答 → 追问 → 重开历史 → 删除。检查相机拒绝授权、无网络、无效密钥、余额不足、限流、超时和图片异常的反馈；未能真实触发的服务错误可以用模拟验证处理逻辑。
6. 真实模型验收：在有用户测试条件时，对照参考答案覆盖单选、多选、填空、简答、完整心电图、影像图及完整图+局部图。逐题记录题型、来源/合成说明、参考答案、识别偏差、答案一致情况与看不清的细节。不要用少量样本推导准确率，也不能以演示模式替代真实模型验证。
7. 更新 R5 文档、构建产物信息和交接报告。

## 5. 原审查模型的验收标准

验收时重新阅读实际代码与新增/未跟踪文件，不仅阅读实施报告。优先复核 R1 的控制流、R2 原图与新图独立性、R3 文案和存储/网络事实、R4 响应到历史展示的完整链路；运行可用的针对性回归，再检查构建与文档证据。

最终结论分开给出：

- **代码与自动验证通过**：必修项实现完整，针对性回归及基础检查通过，没有阻断核心流程的问题。
- **设备与真实模型验收通过**：已提供并复核设备流程及真实题目测试证据。
- **待验收/不通过**：缺少必要运行条件、证据不足、测试失败或缺陷未解决；逐项说明原因和下一步。代码检查通过不能代替设备与真实模型验收。

任何未执行的项目都不能勾成通过；不得仅因 APK 能构建、演示页面能运行或已有旧报告，就认定修复已完成。
