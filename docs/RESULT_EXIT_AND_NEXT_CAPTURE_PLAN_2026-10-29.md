# 离开解析页停止生成、拍摄下一题：实施与验收方案

日期：2026-10-29。仅交付方案，业务代码和 APK 由实施模型修改，随后独立验收。

## 1. 产品行为约定

用户要求：退出题目解析页就暂停解析；解析结果页增加“拍摄下一题”。本方案针对 Android 真机版，Web 不作为本次必改范围。

“暂停”在本项目中按**停止当前网络请求**实现。不是只停止界面刷新，也不设计流的断点续传。回到旧题不自动发请求，用户可点“重新解析”重新请求。不能声称客户端停止后服务端绝不会再计费。

默认把离开题目路由、应用切后台和锁屏都视为不再查看当前题；旋转屏幕、重组、权限弹窗等短暂失去焦点不等同于退出。后台策略如果用户后续指定不同偏好，以用户要求为准。

| 情况 | 期望行为 |
| --- | --- |
| 仍在生成：只有等待状态、正在思考、已出现答案预览、仍在生成详细解析 | 离开时停止本题请求和进度计时，保留题目及可恢复内容，标记未完成 |
| 正式答案已保存、请求已结束 | 离开不改变答案、历史、收藏或完成状态 |
| 对旧答案重新解析中 | 离开时取消此次重答，保留原正式答案和原元信息；输入已修改时保持“答案待更新” |
| 追问正在生成 | 离开时停止本题追问；保留用户消息，已有部分回复明确标记“已停止，内容未完成” |
| 再次打开旧题 | 展示已保存内容及停止说明，不自动解析或自动重发追问 |
| 点“拍摄下一题” | 先停止旧题活动请求、完成必要保存，再进入独立新题拍摄流程 |

不为离开或拍下一题增加确认弹窗。已移除的每次拍题隐私勾选与追加图片确认不恢复。

## 2. 当前代码依据与改动位置

- `app/src/main/java/com/xjb/medicalquestionai/ui/AppNavigation.kt`：全局共享 MainViewModel，home/camera/history/settings/result/{questionId} 路由。离开结果页通常不会销毁 ViewModel，所以请求可继续运行。
- `ui/screens/ResultScreen.kt`：返回按钮直接 popBackStack；无统一“离开此题”处理。生成状态、答案卡、追问输入和追加图片均位于此页。
- `MainViewModel.kt`：analysisJob、activeQuestionId、activeRequestId、followUpJobs；现有 cancelAnalysis 是全局取消，不能直接在旧页面的销毁回调中无条件调用。
- `data/DeepSeekClient.kt`：已有取消底层 OkHttp Call 的链路，优先复用并验证。
- `ui/screens/CameraScreen.kt`：拍摄成功导入图片后直接 popBackStack。若从结果页直接 navigate(camera)，就会回到旧结果页；必须明确相机入口和返回目标。
- `MainViewModel.kt` 的 addCameraImage/importImages 与 ImageStore：处理图片归属及异步导入，下一题不能继承旧图片，也不能误删历史图片。

## 3. 工作包 A：统一停止与页面生命周期

### A1. 建立按题目和请求身份限定的停止入口

建议接口（名称可调整，语义必须保留）：

```kotlin
suspend fun stopQuestionWork(
    questionId: String,
    reason: StopReason,
    expectedRequestId: String? = null
): StopOutcome
```

StopReason 至少区分离开页面、进入后台、拍下一题和用户主动停止。入口要求：

1. 只停止 questionId 对应的分析/重答和追问，不误停另一题。结合 requestId 或任务会话标识拒绝旧页面的迟到停止事件。
2. 幂等：返回按钮、导航监听、后台事件重复到达，不重复写停止回复、不重复清理、不弹多次错误。
3. 取消 Job 后等待底层请求与必要保存完成，释放单任务锁；使用有界等待。若超时，明确提示“旧任务仍在停止，请重试”，不能静默启动下一题与旧题竞争。
4. 网络增量、完成事件和 DB 提交都检查当前任务身份，停止后迟到结果不能把旧题重新写成 completed，也不能污染下一题。
5. 状态记录清楚区分“请求仍在生成”和“最终结果提交中”：最终提交已开始时，允许有界完成不可分割的本地提交，再结束任务；不要在多阶段保存中途取消，留下永久 saving。导航仍可立即响应，拍下一题需等待任务释放。
6. 停止失败、保存失败要有真实错误状态，不能为了进入新相机直接清空所有任务状态。

### A2. 覆盖所有离开路径

至少覆盖顶部返回、系统返回/手势、导航去其他页面、拍下一题，以及应用真正进入后台/锁屏。

实现上以路由身份/可见性协调 ViewModel 为主，按钮调用只提供明确退出意图。不能只改顶部返回，也不能仅依赖 DisposableEffect.onDispose：重组/旋转不应取消；旧路由出栈动画结束后才触发的回调也不能取消新题。

后台处理以真实进入后台为准，避免直接将 ON_PAUSE 全部当退出。配置变更、相机权限弹窗和系统短暂覆盖需要测试；不引入后台服务来继续生成。进程异常终止仍沿用启动时的 interrupted 恢复逻辑，不能承诺系统杀进程时一定来得及补写。

从首页创建任务并导航 result 的过程中，允许一个明确的“进入结果页”过渡；不能因为任务创建时结果页尚未成为当前路由就立即取消。

### A3. 保存语义

- 正式完成结果保留原样；停止不会把它改成取消或空答案。
- 新题生成中停止：保留输入、图片、题型与所选模式。状态可复用 cancelled/interrupted，并用原因文案“已离开页面，解析已停止”。不必为了显示“暂停”引入不具备续传能力的新任务状态。
- 若停止时已有可展示预览，保存为**未完成检查点**，与正式 result 分开；历史重开可显示“未完成预览，需重新解析”，不能冒充正式答案，也不能作为追问上下文/正式答案复制分享。检查点仅保存严格解析后的字段，不将半截 JSON 当正式结果。
- 若需要新增检查点列，使用可空字段及显式 Room 增量迁移；旧数据默认无检查点，禁止破坏式重建数据库。迁移版本以实施时实际版本为起点，本方案不硬编码版本号。
- 重答停止保留旧正式结果；已修改输入的版本标记继续生效。未完成检查点不能覆盖旧正式结果。
- 追问取消可复用已有部分回复保存能力，但确保停止标记/failed 属性使其不会混入下一轮有效上下文；没有正文时只保留原用户消息和停止状态。

推荐展示文案：“已停止解析。返回后不会自动继续，可重新解析。”已保存答案无需额外停止提示。

## 4. 工作包 B：“拍摄下一题”入口及新题流程

### B1. 按钮位置与状态

- 在 ResultScreen 底部固定操作区加入相机图标和完整文字 **拍摄下一题**；答案出现前、生成中、成功、失败和已停止时均可使用。
- 推荐放在追问输入区上方的一行，主按钮高度至少 48dp，横向填满可用宽度。答案详情很长或滚动到追问末尾时仍能找到入口。
- 键盘展开时可以收起这一行以保留输入空间，关闭键盘后立即恢复；不遮挡系统手势区或追问发送/停止按钮。
- 正在执行“停止旧任务/准备下一题”时显示“正在准备…”并禁用重复点击；释放锁后恢复。无需额外确认。
- 按钮的行为是新题拍摄，不是“给当前题追加图片”；当前补充图片入口保留原含义。

### B2. 导航与草稿归属

推荐目标栈为 `home(新题确认页) → camera(新题拍摄)`，并明确相机来源是 next_question；可用等价路由实现，但不能依赖“上一页恰好是首页”。

流程：

1. 捕获旧 questionId/请求身份，进入按钮防重复状态。
2. 调用 stopQuestionWork(旧题, NEXT_QUESTION)，等待停止与必要保存落定；完成的旧题只做幂等检查。
3. 准备一个新的草稿会话，默认题型 AUTO，文字为空、图片为空；沿用当前全局模型/模式。旧题识别文本、图片、追问和 answerRevision 不复制到新草稿。
4. 若首页另有未提交草稿，先暂存为独立草稿，不能静默覆盖或删除其图片。本轮只要求自动保留一个既有草稿并提供恢复入口，不要求建立复杂草稿箱。不得用确认弹窗打断拍摄。
5. 进入相机。拍照成功后进入新题确认页，可以补图、编辑题干、选择题型，再按现有“开始解析”创建新的 questionId；默认不自动上传、不自动发模型请求。
6. 相机取消、权限拒绝或拍摄失败：回新题确认页/提供重拍入口，不把图片塞回旧题，不创建空历史记录。旧题仍可从历史查看（关闭历史保存时按既有临时题策略处理）。
7. 连续拍下一题不无限堆叠旧结果页/相机页；系统返回不重新触发相机、不自动重新解析旧题。返回栈恢复策略必须写进交接报告。

### B3. 异步相机与图片文件

- 给新草稿及相机导入绑定会话 ID。用户取消或离开后，迟到的拍照/压缩回调不能把图片添加到别的草稿，也不能执行过期的 popBackStack。
- 历史题目引用的图片不随新草稿重置而删除。未采用的临时拍摄文件在引用释放后清理，不能一刀切删除整个图片目录。
- 等待导入期间禁止重复拍摄/切换草稿操作造成混入；失败要释放 preparing/isImporting 锁。

## 5. 实施顺序与边界

1. 先实现带任务身份的停止入口及测试，再接路由/后台事件。
2. 处理停止后的结果、检查点与追问状态，补充必要迁移。
3. 实现下一题草稿会话与相机返回目标，再添加固定按钮。
4. 补导航竞争、迟到回调、文件归属和布局回归；生成 APK 和交接报告。

保留前轮已经通过的严格 JSON 空值处理、非法预览降级、answerRevision 追问隔离、编辑成功回调和错误处理。不趁本次调整模型参数、答案协议、速度默认模式；不增加每次隐私勾选。

## 6. 独立验收矩阵

| 编号 | 操作 | 必须看到的结果 |
| --- | --- | --- |
| N01 | 纯文字/图片题开始后立即顶部返回 | 旧 Call 取消、无后续 completed；重开为停止态，输入图片仍在 |
| N02 | 已有答案预览但详情仍生成，系统返回/返回手势 | 停止网络；重开检查点明确未完成，不能当正式答案追问/分享 |
| N03 | 正式结果已保存后返回 | 结果、收藏、模型/用量/耗时不变，无错误取消提示 |
| N04 | 重答中返回，分别测试输入未改和已改 | 保留原正式结果，已改输入继续标过期；不混入本次半成品 |
| N05 | 追问等待/已有部分正文时离开 | 追问停止，原用户文字保留，部分回复标记未完成；重开不自动重发 |
| N06 | 切后台/锁屏；旋转/重组/权限弹窗 | 前两者按方案停止，后三者不被误判退出；无重复状态写入 |
| N07 | 在网络迟到增量/finish/DB 提交边界离开 | 无旧请求复活，无 saving 永久残留，无误覆盖正式结果 |
| N08 | 生成中点拍摄下一题，双击/连续点 | 旧任务结束后只开一个相机，新题不被旧退出回调取消 |
| N09 | 正式完成后点拍摄下一题并拍照 | 拍完进入新题确认，旧题图片/答案不变，新题 ID 独立 |
| N10 | 相机取消、拒绝权限、导入失败 | 有可恢复页面，无空历史；无旧题追加图片，无永久 preparing 锁 |
| N11 | 相机/压缩回调延迟时返回或开启另一个草稿 | 迟到回调丢弃或落到所属会话，不串图、不误导航、不泄漏临时文件 |
| N12 | 首页已有未提交文字/图片，再从历史题拍下一题 | 既有草稿可恢复，其图片未被删除，新题草稿独立 |
| N13 | 连续完成三道题、三次拍下一题，再系统返回 | 栈行为符合约定，无无限堆叠、不重复开相机或重发旧任务 |
| N14 | 360/412dp、深浅色、1.3×字体、键盘及长追问 | 按钮文字可读、至少48dp、可触达、不挡答案/发送/系统安全区 |
| N15 | 停止保存失败、取消超时、新草稿准备失败 | 明确错误，可重试；不假装旧任务已停或静默丢草稿 |
| N16 | 原版数据升级、进程在生成中被终止后重开 | 旧历史正常，新检查点可读；遗留任务中断且不自动联网 |

独立自动检查至少包括：可取消的本地延迟流验证实际断开、带请求身份的停止竞争、预览/旧结果保护、草稿/相机迟到回调与导航目标。不要只断言布尔值变化证明网络已经停止。

生命周期/导航逻辑可抽成可注入控制器，用 fake 请求和仓库在 JVM 验证，不必所有逻辑都等待真机。实际返回手势、后台/锁屏、权限、相机与布局仍需设备测试。

## 7. 交付与验收要求

实施模型提供：

- 改动文件、提交或工作区状态、停止与导航流程说明。
- N01～N16 逐项标明自动/模拟/真机/未执行，附证据；截图至少包括生成中按钮、完成页按钮、相机成功返回的新题确认页。
- Android 单测、Lint、debug 与 AndroidTest 编译结果；如改共享 Web 则补 Web 回归。
- 旧数据库到新版本的迁移证据（如新增字段），网络取消日志及迟到事件不提交的测试。
- 最终 APK 路径、大小、SHA-256，以及输出 APK 与 dist 交付包一致性记录。归档旧包，不覆盖而不留记录。

本方案不要求再次执行完整 40 题质量和速度矩阵才能验证这两个新交互，但旧任务的整体质量/速度待验收状态保持不变；本次不能将未执行项目改成通过。

可直接转交实施模型：请按本文工作包 A/B 实现“离开结果页停止本题分析与追问”和“拍摄下一题”，执行 N01～N16，保留前轮修复；无设备/真实 Key 的检查继续如实标未执行。完成后由当前审查者独立验收，不修改本文或旧验收报告为自行通过。
